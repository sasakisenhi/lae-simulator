# LAE課題・要求定義資料｜文書索引

> すべて架空企業LAEのシナリオ上の前提であり、実在企業の内部情報ではない。人数・件数・時間・比率は実測値ではない。

## 目的と対象範囲

架空企業の現状を先に定義し、**観測された問題 → 利用者への影響 → 原因仮説 → 要求・制約**を検討するための資料群である。技術記事や実装に向けた問題理解が目的だが、この版では**解決策を選ばない**。

> 会社、社員、プロジェクト、数値は創作であり、実在企業の実情・未公開情報を示さない。既存製品・技術名は現行環境の説明であって、導入推奨ではない。

## 記述区分

- **[設定]** 架空企業の業務上の前提として置く事実（実測ではない）。
- **[仮説]** 原因・影響などの暫定的解釈。反例・競合仮説を残す。
- **[要求]** 利用者や組織に必要な状態。実現方式を指定しない。
- **[未決定]** 設定・計測定義・基準など、今後定める事項。
- **[参考]** 実在企業の公開情報。架空企業の事実を裏づけない。

## 変更ルール

1. 個々の事実は表の指定ファイル一箇所に記録する。別資料では原則リンク参照とする。
2. 企業概要は詳細台帳を兼ねない。案件固有の数値・要求はケース側に置く。
3. 要求を技術名・自動化手段・ツール名で記述しない。解決策の検討は別フェーズとする。
4. 要求が検証・調査不足の場合は暫定とし、事実と混同しない。
5. 元資料の `[設定]` は創作上の設定であって観測データの実測ではない。技術的実証・合成データと混ぜない。
6. 元の統合版は比較・追跡用のアーカイブとし、今後の更新対象から外す。

## 3つの課題の関係

2026年10月の全社文脈では、制作担当者が制作に集中できる時間を増やすことを目指す。ただしレビュー待ち、環境提供の待ち、QAの追加確認は別々の課題として扱い、原因を共通化しない。いずれも最初から開発ツールが必要と決めない。

## 今回の分割で保留した領域

元資料にあったAIコードレビュー支援、Terraform/Kubernetes共通化、QAデータ自動収集、PoC評価計画、ADR・記事テンプレートのうち解決策以降の箇所は**現行の要求定義から除外**した。削除ではなく旧版をアーカイブに保存したため、必要になった段階で比較可能である。
