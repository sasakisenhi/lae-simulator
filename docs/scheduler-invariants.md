# G4 Schedulerの検証対象

- 時刻は入力で定めた整数tickとし、正準履歴で逆行しない。
- 予約は `(due_tick, priority, insertion_sequence)` の昇順で消費する。同一tickでは 10、20、30、40、90 の順とし、同順位は投入連番順とする。
- 処理済みの順位より小さい順位を同一tickへ遡って追加しない。期限tickでは許可された完了を期限判定より先に処理する。
- 予約IDと投入連番は再利用しない。取消・失効と消費は正準履歴で検証し、取消・失効後の完了を適用しない。
- Replayは各イベント発生時点の状態と因果関係を検証し、終了時の予約状態を復元する。
- 同一条件は独立プロセスでも同一の正準履歴と状態を生成する。目的別乱数は固定入力と安定識別子から生成し、無関係な抽選に依存しない。決定的試験は乱数を使用しない。
- 有限の判断機会で無限に続くゼロ時間の遷移をINVALIDとして検出する。

取消・失効は原因イベントの即時効果として扱い、独立した優先度を与えない。完了10と外部作用20が同tickなら完了が先行する。同順位の外部作用では投入連番が先の原因から後続予約を失効できる。固定期限90は同tickの完了10より後に処理する。

共通核 `simulation/scheduler.py` は予約、消費、取消・失効のキュー遷移を所有する。原因の権限・対象・正準イベントIDの検証は呼び出すReducerの責務である。CF0の既存キューとG3のtimed入力は同じ核に接続する。詳細な入力契約、ゼロ時間上限、抽選監査、互換性と受入テストの対応は [g4-scheduler.md](g4-scheduler.md) に記録する。
